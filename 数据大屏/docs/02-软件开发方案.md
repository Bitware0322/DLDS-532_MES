## 一、技术选型

| 层次 | 选择 | 理由 |
|---|---|---|
| 运行时 | .NET 8（LTS） | 已装 SDK；`BinaryPrimitives` 原生支持大端读取，不需要手写字节翻转 |
| UI | WPF（MVVM） | 大屏需要高密度自定义绘制、动画、无边框全屏，WPF 的控件模板与矢量渲染比 WinForms 更合适 |
| PLC 通信 | `S7netplus`（命名空间 `S7.Net`） | 纯托管，无第三方 DLL 依赖，支持 `ReadBytes(DataType.DataBlock, db, start, count)`；S7-1200 需勾选 PUT/GET |
| 通信备选 | `Sharp7` / P/Invoke `snap7.dll` | 若 S7netplus 在现场出现会话异常，切到备选。**已用 snap7 完成现场验证，路径确定可行** |
| 图表 | **自绘 TrendChart 控件**（原计划 LiveCharts2） | 阶段二实施时改为自绘：无第三方/原生依赖，风格完全贴合深蓝工业风；功能（多曲线、窗口切换、暂停、清空、自动滚动）全部具备。见 `docs/03` 第六节 |
| 存储 | SQLite（`Microsoft.Data.Sqlite`） | 单文件、免安装、WAL 模式并发读写 |
| 打包 | `dotnet publish` self-contained + Inno Setup | 目标机无需装 .NET；同时提供绿色版 |

通信层做成 `IPlcClient` 抽象，S7netplus 与 snap7 两套实现可切换，避免被单一库卡死。

## 三、线程模型（防卡死的核心）

```
[后台线程] PlcPollingService
     每 500ms → 读 DB120 190B → 解码为 PlcSnapshot（不可变对象）
                                    │
                    ┌───────────────┼────────────────┐
                    ▼               ▼                ▼
             TrendBuffer      AlarmService     DatabaseWriter
             （环形缓冲）      （故障判定）      （批量落库，异步）
                    │
[UI 线程]  DispatcherTimer 150ms 取最新快照 → 刷新 ViewModel → 绑定渲染
```

四条硬约束：

1. **PLC 读取永不在 UI 线程**；读取超时（默认 2000ms）只影响本次快照，不阻塞界面。
2. **图表渲染不等待通信**。图表从环形缓冲取数据，通信断了图表只是停止增长。
3. **UI 按固定频率取「最新快照」**，不做事件风暴推送；500ms 采集 + 150ms 渲染，界面永不堆积。
4. **写库异步批量**（每 5s 或 200 条提交一次），磁盘慢不影响采集。

## 四、数据新鲜度（不允许把旧数据装成实时）

每个 `PlcSnapshot` 带 `ReceivedAt`（本机时间）。界面三态：

| 状态 | 判定 | 表现 |
|---|---|---|
| 实时 | 距上次成功读取 ≤ 2 × 刷新周期 | 数值青色正常显示，右上角绿灯「通信正常」 |
| 过期 | > 2 周期但仍未断链，或 CPU 处于 STOP | 数值变暗 + 角标「数据已过期 3.2s」，顶部黄灯 |
| 离线 | 连接失败 / 读失败 | 数值显示 `--`（**不是 0**），顶部红灯，全屏灰化条 |

CPU STOP 会被单独识别：通信正常但心跳不变，界面提示「PLC 处于 STOP，数据冻结」，不误判为通信故障。

## 七、图表方案

| 项 | 方案 |
|---|---|
| 信号 | 一站深度值、一站转盘角度、二站 8mm 灌注、二站 10mm 灌注、三站称重、三站 X/Y |

| 时间轴 | 固定 5/15/30/60 分钟窗口，随时间右移 |

## 八、SQLite 结构

```sql
trend_samples(ts INTEGER, signal TEXT, value REAL)          -- 索引 (signal, ts)
alarm_events(id INTEGER PK, station TEXT, fault_code INTEGER,
             started_at INTEGER, recovered_at INTEGER, status TEXT, ack INTEGER)
comm_events(id INTEGER PK, ts INTEGER, kind TEXT, detail TEXT)
order_history(order_id INTEGER PK, ab INTEGER, b8 INTEGER, b10 INTEGER, slot INTEGER,
              first_seen INTEGER, last_seen INTEGER, completed_at INTEGER,
              qty_ok INTEGER, qty_ng INTEGER)                -- 由订单 ID 变化软件侧生成
settings(key TEXT PK, value TEXT)
```

保留策略：默认 30 天，每日 03:00 清理；趋势写库按 1s 降采样（500ms 采集不落库），30 天约 250MB 上限，设置项可调 7/30/90 天。

## 九、报警与统计口径（只统计能证实的东西）

| 报警 | 触发 | 恢复 |
|---|---|---|
| 单元故障 | `故障状态 != 0`，记录故障码 | `故障状态 == 0`，写入恢复时间，与发生配对 |
| 心跳停滞 | 心跳值连续 N 个周期不变（默认 5s） | 心跳恢复变化 |
| 通信中断 | 连接/读取失败 | 重连成功 |

**不编造故障名称**：界面只写「故障码 7」，等你提供码表后再做映射（配置化，一处改动）。

订单统计口径：

- 当前订单数量：DB120 订单区订单号非 0 计 1
- 正在加工：`忙碌状态 == 1` 的单元数（0~3）
- 已完成：`order_history` 中 `completed_at` 非空的记录数（软件侧累计，DB120 无历史）
- 合格/不合格：直接取三站 `合格产品计数` / `不合格产品计数`，不另算

## 十、缺失数据清单（DB120 里确实没有，不做假）

| 界面要求项 | DB120 情况 | 处理方式 |
|---|---|---|
| 单元工作时间 | 无此字段 | 软件侧计时：`运行模式==3`（自动运行）的累计时长，提供清零；界面标注「软件计时」 |
| 传输带运行状态 | 无 | **不显示该卡片**，不留空白占位 |
| 轴速度 | 只有位置/角度 | 默认不显示。可在设置中开启「由位移/角度变化率估算」，曲线与数值必须标注「估算值」；建议等 DB 扩展后使用真实速度 |
| 历史订单列表 | 只有当前订单 | 软件侧记录订单切换事件生成历史，标注「本地记录」 |
| 等待加工数量 | 无订单队列 | 不显示；只有「当前订单」1 条 |
| 故障名称 | 只有故障码 | 显示故障码，待你给码表 |
| 产品合格状态含义 | Int，含义未知 | 显示原始数值 + 「待定义」标记 |
| 扫码条码 | Int（装不下条码串） | 按「扫码数值」显示 |

后续扩展建议（DB 层加成即可，不影响现有映射）：`单元累计运行秒数`、`传输带状态 Bool`、`伺服实际速度 Real`、`故障码表`（或在 HMI 用文字数组）。

## 十二、风险与对策

| 风险 | 对策 |
|---|---|
| Real 对齐假设不成立（不同 CPU 固件） | 已用现场 190 字节实测锁定；映射表 `layout.real` 可配，且有黄金样本单测 |
