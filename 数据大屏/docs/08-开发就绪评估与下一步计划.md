### 1.1 一个必须记住的坑

仓库根目录的 `build.log` 内容是「生成失败。0 个警告 0 个错误」——**这不是代码问题**，是沙箱里 MSBuild 节点复用/共享编译被拒导致的静默失败（07 第 9.1 节已记录）。

- 直接跑 `dotnet build` 会复现这个假失败，很容易被误判成"代码坏了"；
- 加 `-m:1 -nodeReuse:false -p:UseSharedCompilation=false` 即恢复正常；
- **后续所有脚本里请统一带这三个参数**，否则每次都会浪费一轮排查。

## 三、三个判断（决定接下来怎么排）

### 判断 1：阶段三不是写代码，是到现场验收 —— 不要空转

`S7FrameSource` 已经写完了：连接带超时箍、失败即关会话、`ReadBytes` 单次读 190 字节、`ReadCpuState` 只认 `8=RUN`。剩下四件事全都要 PLC 通电联网（RUN、PUT/GET 放行、逐字节对照、拔网线重连）。本机 ping 全丢包，做不了。

### 判断 2：阶段五可以完全离线做，而且现在是最佳时机

三条理由，都能在代码里指到位置：

1. **事件源已经真实存在**：`RunEventMonitor` 是唯一事件源，`RunEventLog` 已在写 `%LOCALAPPDATA%\DLDS532\run-events.jsonl`，里面有真实跃变记录。报警页不是从零造，是把已有链路换一个 sink。
2. **趋势接库只差一个出口**：`DashboardViewModel.Refresh()`（`:124`）已经有「≥950ms 入图一次」的闸门，`TrendBuffer` 就是环形缓冲。加历史库＝多一个消费者，图形控件不用动。
3. **模拟源足够验证**：`SimulatedFrameSource` 按真实偏移写 190 字节、48 帧/24 秒一单，能稳定产生订单切换、忙碌跃变、完成跃变——报警配对、历史曲线、保留策略全部可在无 PLC 环境验收。

### 判断 3：阶段六只做「链路预演」，不做正式打包（✅ 已推翻，2026-11-24 正式打包完成）

没有 runtime pack 缓存，首次 `publish -r win-x64 --self-contained` 要联网拉约 100MB+；而且阶段四还要改文案和默认源，现在打包必然返工。建议只验证一次发布链路能跑通，正式包留到最后。

### 6.2 三条设计约束（做阶段五时别踩）

1. **写库绝不进 UI 线程。** 现在趋势入图闸门在 `DashboardViewModel.Refresh()` 里，那是 UI 定时器。历史写入要挂 `PollingService.FrameDecoded`（后台线程），**不要**照抄 UI 里的闸门。
2. **不得引入假数据。** 历史页无记录时显示「暂无历史数据」，不要用趋势缓冲区回填成"历史"。模拟源的历史必须与真实源区分（沿用 `IsSimulation` 标记）。
3. **报警事件不能重复造源。** `RunEventMonitor` 已经是唯一事件源，报警入库应与现有 JSONL 落盘同时进行（或迁移后关闭 JSONL），不能两套逻辑各判一次跃变。

## 七、风险与技术债（07 未覆盖，本次新发现）

| 编号 | 项 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| **R1** | `DashboardViewModel.Refresh()` 每 150ms 发一次 `PropertyChanged(string.Empty)` | `ObservableObject.OnAllChanged()` 用空串通知，WPF 会重算**整棵绑定树**，约 6.7Hz | 现状可接受（三轮 UI 已实测不卡），但这是当前刷新的性能上限 | 阶段五加历史图表时，**不要**用这个节拍做 IO 或重计算；历史图走独立刷新 |
| **R2** | `RunEventLog.Add()` 在 UI 线程同步写文件，`AutoFlush = true` | 每个事件一次刷盘 | 事件稀疏时无感；故障码 0↔非0 反复抖动时会连续刷盘卡界面 | 迁到 SQLite 时改成后台队列，顺手解决 |
| **R3** | `PollingService.FrameDecoded` 在**后台线程**触发 | 注释已写明"订阅方需自行切回 UI" | 阶段五若直接在里面碰 UI 会崩 | A3 直接设计成后台消费、不碰 UI，天然规避 |
| **R4** | `MainViewModel.VersionText` 硬编码 `"v0.5.0  阶段二 · UI R4 · 模拟数据"` | 真实 PLC 下也显示「模拟数据」 | 误导现场人员，属阶段四文案项 | 建议现在改成动态（复用 `SourceBadge` 逻辑），成本一行 |
| **R5** | `artifacts/*.png` 未入库 | 4.5MB，`docs/07` 用它当验收证据 | 图片丢失只能重跑出图 | 正式验收报告把关键截图单独归档 |
| **R6** | 仅有控制台冒烟（56 断言），无 xUnit | 覆盖映射/解码/采集/事件/冻结 | 阶段五引入数据库后覆盖会不够 | 不另起框架，直接在 `SmokeTests` 里加「建表 / 写入 / 保留清理」断言 |
