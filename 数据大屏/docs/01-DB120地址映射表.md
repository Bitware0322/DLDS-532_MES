## 一、结论摘要（先看这三条）

| 项 | 结论 |
|---|---|
| DB120 实际长度 | **190 字节**（读 190 成功；读 191 返回 `0x05 Invalid address`，已实测） |
| 三个站结构起始 | 一站 `0`、二站 `58`、三站 `104`、订单区 `164`（不是 56 / 102，见第五节） |
| 对齐规则 | Int 2 字节对齐、**Real 2 字节对齐（不是 4 字节）**、Struct 起点 2 字节对齐且长度取偶、Bool 按位紧凑、大端、Real 为 IEEE-754 |

> 这三条是本项目全部偏移的地基。第二节给出「Real 必须按 2 字节对齐」的实测反证，请先确认这一条，后面 79 个字段（61 个有语义 ID + 18 个各站保留位）的偏移才成立。

## 二、实测证据链

### 2.1 长度实测

```
db_read(120, 0, 188) → OK
db_read(120, 0, 190) → OK
db_read(120, 0, 191) → FAIL  Read operation failed: Invalid address (0x05)
db_read(120, 0, 198) → FAIL  同上
```

`0x05` 是 S7 的「地址越界」，说明 DB 实际长度就是 190 字节。按导出文件 + 4 字节 Real 对齐推导应为 198 字节，二者差 8 字节 —— 差异来源就是 Real 的对齐方式。

### 2.2 用现场字节反证「Real 2 字节对齐」

现场读到的一站区原始字节（16 进制）：

```
 0: 00 00 00 02 00 00 00 00 00 09 00 00 00 00 5B 5D
16: 00 00 00 00 ...
```

| 读法 | 当前订单ID | 心跳值 | 结论 |
|---|---|---|---|
| Real 按 4 字节对齐（当前步骤@12） | @8 = 9 ✔ | 心跳落在 @16 = 0 ✘ | 与「心跳是递增计数器」矛盾，且下游全部错位 |
| **Real 按 2 字节对齐（当前步骤@10）** | @8 = 9 ✔ | **@14 = 0x5B5D = 23389** ✔ | 三项自洽 |

只有当「当前步骤」占 10~13、心跳落在 14 时，一站区才能与二站区、订单区同时对上。二站、三站重复同样的验证，三个站一起成立，因此这不是巧合。

### 2.3 跨区一致性校验（最强证据）

现场一次读取后，用本表的偏移解码，得到：

| 校验点 | 一站 | 二站 | 三站 | 订单区 | 是否自洽 |
|---|---|---|---|---|---|
| 当前订单 ID | 9 | 9 | 0 | 9 | 一站/二站与订单区一致 ✔（三站当前未接单，订单号仍为 0） |
| 运行模式 | 2 自动待机 | 2 自动待机 | 2 自动待机 | — | ✔（当时 CPU=STOP、单元空闲，2=自动待机合理） |
| 忙碌 / 故障 | 0 / 0 | 0 / 0 | 0 / 0 | — | ✔ |
| 心跳值 | 23389 | −1928 | −29739 | — | ✔（Int16 计数器回绕后的取值，见 2.4） |
| 订单区物料 | — | — | — | `ab物料=1`(A 料)、8mm=2、10mm=2、仓位=4、开始信号=1 | ✔ 语义合理 |

**如果二站按 56 起、三站按 102 起解码**（前一个 MES 项目的做法），会得到「二站忙碌状态 = 2」「三站在线状态 = 111」，而忙碌状态只有 0/1 两种取值 —— 直接不成立。按 58 / 104 起解码，则在线=1、模式=2、忙碌=0、故障=0，全部合法。

### 2.4 关于心跳值显示

三个心跳为 23389 / −1928 / −29739，按 Int16 有符号解会出现负数。它们实际是**持续自增的 16 位计数器，超过 32767 后回绕**成负数。因此界面上不做「数值大小」判断，只判断**是否变化**；如需显示数值，按 UInt16 显示（−1928 → 63608）。

### 2.5 运行模式（`runMode`）取值定义

按现场定义，三个站的 `运行模式` 取值含义如下（**不是** SCL 导出注释里写的那一套）：

| 值 | 含义 | 界面文字 | 界面颜色 |
|---|---|---|---|
| 0 | 未知 | 未知 | 灰 |
| 1 | 手动模式 | 手动 | 常规文字 |
| 2 | 自动待机模式 | 自动待机 | 橙 |
| 3 | 自动运行模式 | 自动运行 | 绿 |

> SCL 导出的行注释写的是「0 手动 / 1 自动待机 / 2 自动运行」，与现场不符，属导出遗留文字，**以现场定义为准**。
> 只有 `=3`（自动运行）计入单元工作时间；`=2`（自动待机）不计。
> 实现集中在 `RunModeText`（`Enums.cs`）：`Describe()` 出文字、`IsRunning()` 判工时，界面与事件检测都从这里取，避免多处各写一套。

## 三、布局规则（S7-1200 非优化块）

| 类型 | 长度 | 对齐 |
|---|---|---|
| Bool | 1 位 | 按位紧凑，8 位凑满一字节 |
| Byte / SInt / USInt | 1 字节 | 1 字节 |
| Int / Word / UInt | 2 字节 | **2 字节**（偏移必须为偶数） |
| Real / DInt / DWord | 4 字节 | **2 字节**（实测结论，见 2.2） |
| Array of Bool | ⌈n/8⌉ 字节 | 从新的字节边界（**bit 0**）开始 |
| Array of 其他 | n × 元素长度 | 元素对齐 |
| Struct | 见各段 | 起点 2 字节对齐，长度向上取偶 |

字节序：**大端**（高字节在前）。Real：IEEE-754 单精度，`BitConverter` 需先反转字节序（或使用 `BinaryPrimitives.ReadSingleBigEndian`，.NET 8 已内置）。

## 六、读取策略与安全边界

| 项 | 方案 |
|---|---|
| 读取方式 | **整块读取** `DB120, start=0, size=190`，一次拿全，保证同一时标下数据一致（分段读会有撕裂风险） |
| 长度校验 | 读取长度必须是 190；返回值长度不符直接判失败，不使用半截数据 |
| 越界保护 | 所有字段偏移 + 长度必须 ≤ 实际返回长度，否则该字段标记 `Invalid` 而不是抛异常 |
| 字节序 | 大端；`BinaryPrimitives.ReadInt16BigEndian` / `ReadSingleBigEndian` |
| 写入 | **禁止**。本软件无任何写 PLC 的代码路径，通信层只暴露 `Read`；DB120 全表 `rw = "R"` |
| CPU 状态 | 现场 CPU 处于 STOP 时数据静止，界面必须能区分「STOP/数据冻结」与「通信正常」 |
